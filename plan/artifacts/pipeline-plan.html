02 Instruction Tuned NEW
125M Gemma 2B

What it is

Further fine-tune the QA SFT models on an instruction-following dataset so they can handle general instructions, not just QA extraction. This is the base checkpoint that feeds both the RLAIF and DPO branches.

Data

  • Create data/instruction_train.jsonl via Azure GPT — generate diverse instruction–response pairs from the SFT prompts plus new synthetic instructions (coding, summarization, reasoning, multi-step tasks)
  • Target ~2,000 examples (enough to shift behavior without catastrophic forgetting of QA)
  • Format: same chat-messages JSONL as sft_train.jsonl
  • Azure GPT generates high-quality responses; LLM judge filters low-quality pairs

Scripts to create

  • shared/create_instruction_data.py — Azure GPT pipeline to generate instruction dataset (reuse the async+semaphore pattern from gemma2b/create_preference_data.py)
  • shared/instruction_tune.py — generic instruction-tuning script that takes --model, --data, --output. Full-parameter for 125M, QLoRA for Gemma 2B (auto-detect by param count)

Makefile targets

# Data generation $ make create-instruction-data ARGS="--n-samples 1000" # Training $ make instruction-tune-125m $ make instruction-tune-gemma

Output paths

  • models/slm125m/instruction
  • models/instruction_local/adapter (Gemma 2B QLoRA adapter)
  • models/instruction_local/merged (merged into base)

Key decisions

  • Use a shared/ package for scripts used by both model sizes, to avoid the current duplication between gemma2b/ and slm125m/
  • Instruction data should be diverse — not just legal/financial. Mix in general reasoning, summarization, and multi-step tasks so the model generalizes
  • Training: 2–3 epochs, low LR (1e-5 for 125M, 2e-5 QLoRA for Gemma) to avoid forgetting QA knowledge
3A RLAIF NEW
125M 2B

What it is

True RLAIF (RL from AI Feedback): train a reward model scored by an AI judge, then use PPO/REINFORCE to optimize the instruction-tuned model against that reward signal. Distinct from DPO — this learns an explicit reward function.

Pipeline

  • Step 1 — Reward data: Sample prompts, generate N responses per prompt from the instruction-tuned model, have Azure GPT rank/score them. Save as data/reward_train.jsonl
  • Step 2 — Reward model: Fine-tune a reward model (add a scalar head to the 125M SFT model). Trained on the ranked pairs to predict human-aligned scores
  • Step 3 — RL training: PPO loop — generate from the policy (instruction-tuned model), score with reward model, update policy. Uses TRL's PPOTrainer

Scripts to create

  • shared/create_reward_data.py — generate + AI-score responses
  • shared/train_reward_model.py — reward model training
  • shared/train_rlaif.py — PPO training loop

Makefile targets

$ make create-reward-data $ make train-reward-model $ make train-rlaif-125m $ make train-rlaif-gemma

Output

  • models/slm125m/rlaif
  • models/rlaif_local/adapter & merged

Timing concern

PPO is slow. For the 125M model on MPS, budget ~30 min. For Gemma 2B, budget ~2 hours on MPS or use Modal. Consider: run reward-data generation in parallel with instruction tuning (they're independent once you have the instruction-tuned checkpoint).

4A RAFT on RLAIF NEW
125M 2B

What it is

RAFT (Retrieval Augmented Fine-Tuning) teaches the model to answer questions using retrieved context, distinguishing relevant documents from distractors. Applied to the RLAIF-trained model.

Data pipeline

  • Take QA prompts from the SFT dataset. For each prompt, create a training example with: the question, one "oracle" document (contains the answer), and K "distractor" documents (irrelevant passages)
  • Azure GPT generates chain-of-thought answers that cite the oracle document and ignore distractors
  • Format: {"question", "context" (oracle + distractors shuffled), "answer" (with citations)}
  • Save as data/raft_train.jsonl

Scripts to create

  • shared/create_raft_data.py — build RAFT dataset from SFT prompts + Azure GPT
  • shared/train_raft.py — fine-tune on RAFT data (SFT-style, but with context-augmented prompts). Auto-detects model size for full-param vs QLoRA

Makefile targets

$ make create-raft-data ARGS="--n-samples 500 --n-distractors 4" $ make train-raft-rlaif-125m $ make train-raft-rlaif-gemma

Output

  • models/slm125m/raft_rlaif
  • models/raft_rlaif_local/adapter & merged

Critical path

The bottleneck is RLAIF: it requires instruction tuning → reward data → reward model → PPO, all sequential. DPO and RAFT data generation can run in parallel alongside the RLAIF chain. Start with instruction data creation (Phase 1) since everything else depends on it.
