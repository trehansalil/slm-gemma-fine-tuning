Stage 3B: DPO on the instruction-tuned models

This is mostly a re-pointing job, not new code. Both DPO scripts already exist and
work fine on the QA-SFT checkpoints (that's Stage 3/RLAIF's DPO branch). Now that
Stage 02 gives us instruction-tuned checkpoints, I want new Makefile targets that
run the exact same DPO trainers but start from the instruction-tuned models
instead, and save to fresh output dirs so we don't clobber the existing DPO runs.

Existing checkpoints to point at:
- Gemma 2B: models/instruction_local/merged  (merged instruction-tuned model)
- SLM 125M: models/slm125m/instruction

Existing scripts (unchanged, just called with different flags):
- gemma2b/train_dpo.py  -- QLoRA DPO. Flags: --sft-model (default models/sft_local/merged),
  --base (default models/base, unused when sft-model is already merged), --data
  (default data/preference_train.jsonl), --output (default models/dpo_local/adapter),
  --epochs (1), --batch-size (2), --grad-accum (4), --lr (5e-5), --beta (0.1),
  --max-length (512), --lora-r (16), --device.
- slm125m/train_dpo.py -- full-param DPO. Flags: --model (default models/slm125m/base),
  --data (default data/preference_train.jsonl), --output (default models/slm125m/dpo),
  --epochs (2), --batch-size (8), --grad-accum (2), --lr (5e-5), --beta (0.1),
  --max-length (512), --device.
  Note: this script's default --model is slm125m/base, NOT an SFT checkpoint -- for
  the instruct target we must explicitly pass --model models/slm125m/instruction.

Data section
------------
Reuse as-is by default: data/preference_train.jsonl (1,379 pairs, prompt/chosen/
rejected format, one JSON object per line). The prompts are legal/financial
domain questions -- they're still relevant regardless of which checkpoint
generates the losing/winning completions, since chosen/rejected were both
generated by Azure GPT (strong-persona vs weak-persona), not sampled from our
own model. So there's nothing inherently "stale" about reusing the file when we
switch to the instruction-tuned checkpoint.

DECIDED: no on-policy preference data. DPO works fine off-policy, the existing
1,379 Azure-generated pairs (strong-persona chosen vs weak-persona rejected,
judge-validated, deduped) are enough, and writing a new self-sampling script buys
us very little against the live-lecture time budget. Do NOT build a script that
samples completions from models/slm125m/instruction / models/instruction_local/
merged for ranking. If we ever just need MORE pairs, the existing generator is
enough: make create-preference-data ARGS="--n-samples 300 --concurrency 30"
(bump --concurrency across multiple Azure keys to keep it fast).

Training section
----------------
New Makefile targets (mirror train-dpo-gemma / train-dpo-slm125m but with new
model + output vars):

  DPO_INSTRUCT_LOCAL   := models/dpo_instruct_local/adapter
  SLM125M_DPO_INSTRUCT := models/slm125m/dpo_instruct

  train-dpo-gemma-instruct: ## DPO fine-tune the instruction-tuned Gemma 2B
      python -m gemma2b.train_dpo --sft-model models/instruction_local/merged \
          --output $(DPO_INSTRUCT_LOCAL) $(ARGS)

  train-dpo-125m-instruct: ## DPO fine-tune the instruction-tuned SLM 125M
      python -m slm125m.train_dpo --model models/slm125m/instruction \
          --output $(SLM125M_DPO_INSTRUCT) $(ARGS)

Run:
  make train-dpo-125m-instruct
  make train-dpo-gemma-instruct ARGS="--epochs 1 --lr 5e-5"

Output paths:
- models/slm125m/dpo_instruct
- models/dpo_instruct_local/adapter  (+ merge step if we want a merged copy,
  same as the existing dpo_local merge pattern)

Acceptance checks
-----------------
- Both targets run end-to-end on MPS without OOM (125M full-param, Gemma QLoRA)
  within a live-lecture time budget (~5-10 min for 125M, ~15-20 min for Gemma
  on 1,379 pairs at defaults).
- Output dirs contain adapter/model + tokenizer files, loadable via
  AutoModelForCausalLM.from_pretrained / PeftModel.from_pretrained.
- Sanity-check a handful of prompts against the pre-DPO instruction-tuned
  checkpoint and confirm the DPO'd model prefers more detailed/structured
  answers (spot check, not a full eval).
- Existing models/dpo_local and models/slm125m/dpo (QA-SFT-based DPO runs)
  are untouched -- new targets write to the _instruct paths only.
